Prompt técnico para Replit
Quiero que construyas una web app mobile-first llamada Vive Valle Play.
Objetivo del producto
La app está diseñada para que personas que ya están juntas en una casa rural, alojamiento, evento o escapada puedan:
•	jugar juntas 
•	reírse 
•	socializar 
•	conectar 
•	improvisar 
•	crear recuerdos 
•	vivir momentos compartidos 
No quiero una app para jugar con desconocidos.
No quiero una red social.
No quiero un videojuego tradicional.
Quiero una app que funcione como un motor de experiencias sociales guiadas, pensada primero para los clientes de Vive Valle, pero construida desde el principio para poder expandirse a otros contextos:
•	casas rurales 
•	hoteles boutique 
•	apartamentos turísticos 
•	campings 
•	eventos privados 
•	cumpleaños 
•	team building 
•	restauración experiencial 
•	turismo y ocio 
La idea central es:
“Menos pantalla pasiva. Más juego, risas y recuerdos juntos.”
________________________________________
Filosofía del producto
La app debe activar la convivencia del grupo.
El objetivo no es “ganar”, sino:
•	romper el hielo 
•	generar conversación 
•	provocar risas 
•	fomentar creatividad 
•	facilitar momentos memorables 
•	crear recuerdos compartidos 
La app debe hacer que la gente:
•	se mire 
•	se escuche 
•	se pique sanamente 
•	improvise 
•	hable entre sí 
•	se divierta en grupo 
________________________________________
MVP que quiero construir
Quiero una v1 sencilla, funcional y bonita, con una arquitectura sólida para poder crecer después.
Esta primera versión debe incluir:
1. Pantalla de bienvenida
Una home clara y atractiva.
Debe incluir:
•	logo o título: Vive Valle Play 
•	subtítulo tipo:
“Juegos y momentos para disfrutar juntos” 
•	CTA principal: Empezar 
•	diseño cálido, limpio y muy visual 
________________________________________
2. Selección de tipo de grupo
El usuario debe poder elegir el tipo de grupo:
•	Familia 
•	Amigos 
•	Pareja 
•	Grupo mixto 
No hace falta registro.
Esto debe servir para adaptar el tono y las recomendaciones.
________________________________________
3. Selección de momento
La app debe preguntar en qué momento están:
•	Acabamos de llegar 
•	Tarde tranquila 
•	Antes de cenar 
•	Noche 
•	Despedida 
Según esta selección, la app recomendará juegos o packs concretos.
________________________________________
4. Biblioteca de experiencias
La app debe contener una biblioteca de juegos y dinámicas sociales.
Cada experiencia debe tener:
•	id 
•	título 
•	descripción 
•	categoría 
•	duración estimada 
•	dificultad 
•	tipo de grupo recomendado 
•	momento recomendado 
•	número ideal de personas 
•	lista de rondas o pasos 
•	sistema de puntuación opcional 
•	cierre final 
________________________________________
5. Modo juego guiado
Cada juego debe mostrarse paso a paso.
Cada paso o ronda puede incluir:
•	título 
•	instrucción breve 
•	tipo de interacción 
•	botón siguiente 
•	temporizador opcional 
•	puntuación opcional 
•	pista opcional 
Tipos de interacción que quiero soportar en esta v1:
•	solo lectura / instrucción 
•	votación interna del grupo 
•	texto libre 
•	elección entre opciones 
•	contador manual / completar 
•	reto con temporizador 
•	pantalla de foto final simulada o marcador de “foto hecha” 
No necesito cámara real obligatoria en esta versión.
________________________________________
6. Pantalla de resultados
Cada experiencia debe acabar con una pantalla final que muestre:
•	título del grupo o resultado 
•	frase final 
•	puntos si aplica 
•	recuerdo generado 
•	botón para volver al inicio 
•	botón para jugar otra experiencia 
________________________________________
7. Pantalla de recuerdo
Debe existir una pantalla sencilla donde se pueda mostrar algo como:
•	nombre del grupo 
•	lema 
•	frase del viaje 
•	categoría divertida obtenida 
•	resumen del momento 
•	espacio para una foto simbólica o marcador de recuerdo 
No hace falta persistencia avanzada todavía, pero sí una estructura preparada para guardarlo más adelante.

•	resultado final o recuerdo simple

Modelo de datos
Quiero un modelo claro y escalable.
Tipo Game
Debe incluir algo así:
type GameStepType =
  | "intro"
  | "vote"
  | "text"
  | "choice"
  | "timer"
  | "challenge"
  | "memory"
  | "result";
type GameStep = {
  id: string;
  title: string;
  description: string;
  type: GameStepType;
  options?: string[];
  durationSeconds?: number;
  points?: number;
  hint?: string;
};
type Game = {
  id: string;
  title: string;
  slug: string;
  description: string;
  category: string;
  durationMin: number;
  difficulty: "easy" | "medium" | "fun";
  recommendedGroups: string[];
  recommendedMoments: string[];
  minPlayers: number;
  maxPlayers?: number;
  steps: GameStep[];
  endingTitle: string;
  endingDescription: string;
};

Motor de recomendación simple
La app debe recomendar juegos según:
•	tipo de grupo 
•	momento del día 
Ejemplo:
•	Familia + Acabamos de llegar → El Juicio de la Casa 
•	Amigos + Antes de cenar → La Cena Imposible 
•	Pareja + Noche → experiencia más íntima o creativa 
Hazlo con lógica simple basada en filtros y prioridad.
